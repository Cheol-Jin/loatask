# 홈 화면

## 사용 흐름

- `/`: 검색창, 최근 검색, 공식 소식, 진행 중인 이벤트, 즐겨찾기, 누적 검색 TOP 5, 운세 바로가기.
- `/?character=캐릭터명`: 기존 검색 결과와 즐겨찾기/누적 검색 TOP 10 유지.
- 로고나 상단 캐릭터 검색 메뉴를 누르면 홈으로 돌아갑니다. 이전 검색 결과는 홈에서 숨기고, 진행 중인 검색 응답이 나중에 홈 상태를 덮지 않도록 무효화합니다.
- 최근 검색은 성공한 캐릭터 이름만 브라우저에 최근 순 5개까지 저장합니다. 동일 이름은 앞으로 이동하며, 눌러 다시 검색할 수 있습니다.

## 코드 읽는 순서

1. `CharacterListView.vue`: URL의 character 유무로 홈/검색 화면을 전환합니다. URL 변경을 감시하고 한 번만 검색하여 중복 API 요청을 피합니다.
2. `HomeNews.vue`: 공지와 이벤트를 독립적으로 불러오고, 각각 로딩·빈 상태·오류·재시도를 표시합니다. 전체 공식 페이지 링크도 제공합니다.
3. `utils/homeNews.ts`: 공지 최신 5개, 이벤트 종료 가까운 순 최대 2개, KST 일정 처리와 공식 HTTPS 링크 검증.
4. `recentSearchStore.ts`: localStorage의 `loatask.recent-searches.v1`에 성공 검색 이름을 저장합니다. 저장 실패는 검색 성공 자체를 막지 않습니다.
5. `HomeFortune.vue`: 기존 씨앗 그림과 Pinia 운세 기록으로 남은 기회를 보여줍니다. 클릭 전에는 추첨 횟수를 소비하지 않습니다.
6. `LostArkHomeController`: GET /api/lostark/home/notices, GET /api/lostark/home/events 제공.
7. `LostArkNewsClient`: 공식 /news/notices와 /news/events를 서버의 기존 API 키로 조회합니다. 키를 브라우저에 전달하지 않습니다.
8. `CharacterResponseCache`: 기존 캐릭터 캐시 기본 정책은 유지하고, 소식 캐시만 정책을 별도로 지정합니다.

## 데이터와 갱신

공식 소식은 각각 하나의 캐시로 모든 방문자가 공유합니다. 10분 동안 재사용하고 만료 뒤 다음 요청에 갱신합니다. 일시 연결 오류·429·5xx 시 마지막 성공 데이터가 1시간 미만이면 대신 반환하고, 1분간 재호출을 쉽니다. 인증 오류나 잘못된 응답은 기존 데이터로 숨기지 않습니다. 메모리 캐시이므로 서버 재시작 시 사라집니다.

지표 로그에는 NOTICE/EVENT 종류를 추가했습니다. 캐릭터 PROFILE/ARMORY/ROSTER 지표와 분리하며, 공지·이벤트 요청은 검색 횟수를 증가시키지 않습니다.

시차가 없는 공식 날짜는 한국 시간으로 해석합니다. 진행 중인 이벤트만 표시하고, 브라우저에서 30초마다 현재 시간을 확인해 종료된 이벤트를 숨깁니다. 실제 API 재호출을 30초마다 수행하는 것은 아닙니다. 공식 페이지가 최종 기준이며 캐시 갱신 전에는 변경 사항이 늦게 반영될 수 있습니다.

외부 링크는 공식 HTTPS 호스트만 허용하고 새 탭에서 엽니다. 썸네일을 읽지 못하면 제목과 일정은 계속 표시합니다. 공식 정보 조회가 실패해도 캐릭터 검색·브라우저 즐겨찾기·운세는 각각 이용할 수 있습니다. 캐릭터 상세를 즐겨찾기 개수만큼 자동 조회하지 않습니다.

## 검증

- 백엔드 빌드 및 테스트 60개 통과. 기존 캐릭터 캐시 정책 회귀 테스트와 소식 매핑/캐시/일시 오류/최대 보관 시간/인증 오류 비노출/독립 요청 검증 포함.
- 프론트 타입 검사·빌드 및 테스트 39개 통과. 최신순/공식 링크/한국 시간/종료 이벤트/최근 검색 저장·정렬·오류 검증 포함.
- 로컬 모의 데이터로 공지 실패와 독립 재시도, 이벤트 유지, URL 검색, 홈 복귀, 최근 검색 재조회, 누적 순위와 운세 배치 확인.
- 두 번 검색했을 때 모의 프로필 API 호출도 두 번으로 확인했습니다.
- 실제 운영 DB·비밀 설정을 변경하지 않았고, 배포 서버의 실제 공지·이벤트 데이터 표시까지는 아직 미확인입니다.
