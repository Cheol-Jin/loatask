# 욤의 운세: 36장과 하루 두 번 추첨

## 동작

- 오늘의 모험, 레이드 전 한 장, 이번 주 원정대 각각 36개 결과를 제공합니다. 카드 36장에 항목별 해석 3개씩, 총 108개입니다.
- 각 항목은 하루 최초 1회와 다시 뽑기 1회까지 이용할 수 있습니다. '이번 주 원정대'도 요청대로 일일 제한을 적용합니다.
- 카드를 실제로 누르고 기록 저장이 성공했을 때만 한 번 사용합니다. 다시 뽑기 버튼을 눌러 섞기만 한 상태에서는 차감하지 않습니다.
- 두 번째 카드에서는 같은 항목의 첫 번째 카드를 제외합니다.
- 페이지를 새로고침하거나 다른 항목으로 이동했다 돌아와도 마지막 결과와 사용 횟수가 유지됩니다. 다른 항목의 횟수에는 영향을 주지 않습니다.
- 한국 시간(Asia/Seoul) 날짜가 바뀌면 초기화됩니다. 화면은 30초마다 및 창 포커스/탭 복귀 시 기록을 확인하고, 실제 추첨 직전에도 날짜를 확인합니다.
- 결과는 하루 마지막 카드 하나를 화면에 복원합니다. 이전 날짜의 기록은 새 날짜의 첫 저장에서 대체하므로 보관량은 증가하지 않습니다.

## 왜 Pinia와 localStorage를 함께 쓰나요?

Pinia는 실행 중인 Vue 화면이 사용할 상태를 공유하고 반응형으로 갱신합니다. Pinia만으로는 새로고침 이후 기록이 남지 않으므로 localStorage에 일자와 항목별 카드 ID를 함께 저장합니다. 서버나 AI API를 호출하지 않습니다.

저장 키는 `loatask.fortune.v1`입니다. 사용자 고민이나 계정 정보는 저장하지 않습니다.

## 코드 읽는 순서

1. `src/data/fortune.ts`: 36장과 각 항목의 해석을 정의합니다. shuffleFortuneCards의 제외 ID 인자로 첫 카드를 빼고 다시 섞습니다.
2. `src/stores/fortuneStore.ts`: Pinia 상태와 날짜 변환, 기록 검증, 남은 횟수, 저장을 담당합니다. sync로 저장 직전 다른 탭의 최신 기록도 읽습니다.
3. `src/views/FortuneView.vue`: 항목 변경, 결과 복원, 카드 선택, 다시 뽑기, 횟수 안내와 일일 제한 표시를 담당합니다.
4. `src/components/FortuneArtwork.vue`: 직접 그린 씨앗·새싹 캐릭터와 결정·관문·범선·무기·책·깃털·상자·나무·모닥불 소품을 SVG로 표시합니다. 카드별 색/소품을 달리하며 공식 이미지를 다운로드하거나 복사하지 않았습니다.

## 저장과 동시 사용

- 저장 실패 시 화면에 실패를 안내하고 새 결과와 사용 횟수를 확정하지 않습니다.
- 읽기 차단이나 손상된 기록을 만나면 무제한 추첨으로 바꾸지 않고 일단 추첨을 중단합니다.
- storage 이벤트로 다른 탭의 변경을 반영합니다.
- Web Locks 지원 브라우저에서는 동일 저장 키의 추첨을 잠금으로 직렬화합니다. 미지원 환경에서는 저장 직전 재조회하지만 여러 탭의 동시 추첨에 대한 엄격한 원자성까지 보장하지 않습니다.

## 적용 범위

**같은 브라우저·같은 사이트 주소의 저장 공간 기준**입니다. 다른 브라우저/기기, 시크릿 창, 저장 데이터 삭제, 사용자 시계 조작을 막는 서버 검증이 아닙니다. localhost와 배포 주소도 서로 기록을 공유하지 않습니다. 계정 단위의 엄격한 하루 제한은 로그인과 서버 저장이 필요합니다.

## 검증

Node 24로 frontend 폴더에서 다음을 실행합니다.

```sh
npm exec --yes --package=node@24 --call 'npm run build && node --test tests/*.test.mjs'
```

타입 검사·프로덕션 빌드 및 프론트 테스트 33개 통과. 새 테스트는 36장/108개 해석, 재추첨 제외, 항목별 2회, 결과 복원, KST 자정, 저장 오류와 손상 데이터, 여러 스토어의 기록 공유 등을 확인합니다.

별도 localhost:5174 화면에서 실제 카드 두 번 선택 후 잠김, 새로고침 후 유지, 다른 항목의 독립적인 횟수, 그림과 해석 표시, 콘솔 오류 없음을 확인했습니다. 배포 화면은 아직 재확인하지 않았습니다. 기존 localhost:5173 및 배포 사이트의 사용자 기록은 건드리지 않았습니다.
