# 캐릭터 조회 API 캐시

검색 순위 집계는 그대로 두고, 백엔드에서 공식 API를 호출하는 부분에만 캐시를 적용했습니다.

| 항목 | 정책 |
| --- | --- |
| 키 | 앞뒤 공백을 제거한 캐릭터명. 기본 프로필·상세정보·원정대 목록은 별도 캐시 |
| 보관 개수 | 서버 프로세스당 기본 프로필 256개, 상세정보 64개, 원정대 목록 128개. 한도를 넘으면 가장 오래 사용하지 않은 항목 제거 |
| 갱신 | 성공 응답은 60초간 바로 재사용. 60초 이후 다음 조회에서 갱신하고, 조회가 없으면 호출하지 않음 |
| 동시 조회 | 같은 종류와 같은 이름에 대한 갱신 요청이 겹치면 하나의 공식 API 요청을 공유 |
| 일시 오류 | 연결 오류, 공식 API 429·5xx 발생 시 마지막 성공 응답이 10분 미만이면 대신 사용. 해당 항목은 실패 시점부터 최대 15초간 재호출하지 않음 |
| 이전 응답 없음 | 공식 API 오류 안내를 반환. 10분이 지난 응답도 반환하지 않음 |
| 기타 오류 | 캐릭터 없음, 인증 오류, 해석 불가능한 응답은 숨기지 않으며 해당 캐시 항목을 제거 |

갱신 실패는 마지막 성공 시점을 연장하지 않습니다. 임시 응답은 기존과 같은 JSON으로 반환하므로 화면에서 별도 표시하지 않습니다. 캐시는 재시작하면 사라지고 서버 간에 공유되지 않습니다. 신규 캐릭터를 연속 조회하는 상황에서 전체 요청 한도를 보장하지는 않습니다.

## 비교 방법

동일한 캐릭터를 순차적으로 20번 조회합니다. 두 조건 모두 동일한 백엔드 클라이언트와 응답 데이터를 사용합니다. 기준선은 테스트 시계를 요청마다 60초씩 전진시켜 모든 요청에 외부 호출이 일어나게 했고, 비교군은 60초 이내 반복 조회를 재현했습니다. 모의 공식 API에는 호출마다 80ms 지연을 넣었습니다.

측정 범위는 백엔드 클라이언트 호출부터 반환까지입니다. DB 집계, 브라우저, 실제 네트워크·공식 API·서버 기동 시간은 포함하지 않습니다. 평균과 p95는 첫 조회를 포함합니다. p95는 표본 20개에서 오름차순 19번째 값입니다. 시간은 환경마다 달라질 수 있어 테스트에서는 호출 횟수만 검증합니다.

저장소 루트에서 재현:

```sh
./gradlew test --tests '*CharacterCacheMeasurementTests' --rerun-tasks --no-daemon
```

결과는 Gradle 테스트 보고서의 해당 테스트 클래스 표준 출력에서 `CACHE_MEASUREMENT`로 확인합니다.

## 측정 결과 (2026-11-11)

| 조회 조건 | 조회 수 | 모의 외부 호출 | 평균 | p95 |
| --- | ---: | ---: | ---: | ---: |
| 기준선: 매번 캐시 만료 | 20 | 20 | 87.848 ms | 89.641 ms |
| 캐시: 첫 조회 후 19회 재사용 | 20 | 1 | 5.547 ms | 0.011 ms |

이 반복 조회 조건에서 외부 호출은 95% 줄었습니다. 캐시의 p95에는 가장 느린 첫 호출이 포함되지 않으므로 최초 조회 시간으로 해석할 수 없습니다. 실제 서비스의 지연 개선 수치는 아직 측정하지 않았습니다.
