# 원정대 캐릭터 목록

## 화면 사용

1. 캐릭터 검색 결과에서 **상세 보기**로 이동합니다.
2. 기본 프로필 아래 **원정대 캐릭터**에서 같은 서버의 캐릭터를 확인합니다.
3. 서버 선택에서 다른 서버 또는 전체 서버를 선택할 수 있습니다. 공식 API는 계정의 여러 서버 캐릭터를 반환하므로 같은 서버만 기본 표시합니다.
4. 아이템 레벨이 높은 순서로 정렬되며 현재 조회 중인 캐릭터를 표시합니다.
5. 다른 캐릭터를 누르면 해당 캐릭터의 기존 상세 화면으로 이동합니다. 이동한 캐릭터의 서버가 기본 선택됩니다.
6. 목록만 실패하면 상세 프로필은 유지되고 **목록 다시 시도**로 해당 요청만 재시도합니다.

## 코드 흐름

- `LostArkSiblingResponse.java`: 공식 응답의 ServerName/CharacterName/CharacterLevel/CharacterClassName/ItemAvgLevel을 camelCase로 매핑합니다.
- `LostArkOpenApiClient.getCharacterRoster`: 공식 `GET /characters/{characterName}/siblings`를 호출합니다. 배열 검증 후 수정 불가능한 목록으로 저장합니다. 잘못된 응답은 캐시하지 않습니다.
- `LostArkController`: 프론트가 사용하는 `GET /api/lostark/official/characters/{characterName}/roster`를 제공합니다. 목록 조회 자체는 검색 횟수를 증가시키지 않습니다. 목록에서 실제 상세 조회로 이동하면 기존 상세 조회처럼 증가합니다.
- `CharacterResponseCache`: 목록도 기존 60초 재사용·일시 오류 시 최대 10분 미만의 이전 응답·15초 재호출 유예·동일 이름 요청 병합 정책을 사용합니다. 목록은 최대 128개 키를 보관합니다.
- `CharacterApiMetrics`: ROSTER 종류를 추가해 기본 프로필/상세 지표와 분리합니다. 주기 로그에도 자동 포함됩니다.
- `getCharacterRoster`: 프론트에서 API를 호출합니다. 목록은 기본 프로필 요청과 별도이므로 실패해도 상세 화면 전체를 가리지 않습니다.
- `CharacterRoster.vue`: 목록 로딩·오류·서버 선택·현재 캐릭터 표시·상세 링크를 담당합니다. 이름 변경/화면 종료 후 이전 응답이 새 화면을 덮지 않도록 요청 번호를 확인합니다.
- `utils/roster.ts`: 서버 필터와 아이템 레벨 정렬을 담당합니다. 쉼표를 제거한 숫자로 비교하고, 같은 레벨이면 이름순, 알 수 없는 레벨은 마지막에 둡니다. 원본 배열은 변경하지 않습니다.
- `CharacterDetailView.vue`: 기존 프로필과 상세정보 사이에 목록을 배치합니다.

## 범위와 주의점

서버 선택·정렬은 가져온 목록으로 브라우저에서 처리하므로 추가 공식 API 요청이 없습니다. 계정의 서로 다른 캐릭터 이름을 키로 조회하면 캐시는 별도 항목입니다. 원정대 전체를 알기 위해 다른 캐릭터의 상세 API를 한꺼번에 호출하지 않습니다. 캐시 갱신 전까지 신규 생성/삭제/성장 정보가 즉시 반영되지 않을 수 있습니다.

원정대 목록은 공식 API가 제공한 데이터만 표시합니다. API 키와 운영 DB 데이터는 변경하지 않았습니다. 숙제 체크·원정대 성장 집계·다른 캐릭터의 장비 일괄 수집은 포함하지 않습니다.

## 검증

- 백엔드 빌드 성공, 테스트 53개 통과. 새 테스트에서 응답 매핑, 여러 서버 목록, 캐시 적중, 검색 집계 미변경, 빈 배열, 오류/잘못된 응답, 일시 장애 대체 응답과 재갱신을 확인했습니다.
- 프론트 타입 검사·빌드 성공, 테스트 17개 통과. 서버 필터, 숫자 레벨 정렬, 원본 보존, 누락 값 처리 포함.
- 로컬 모의 데이터로 기본 서버, 전체 서버, 다른 캐릭터 이동, 현재 조회 표시 변경, 목록 오류 후 재시도·빈 상태를 확인했습니다.
- 실제 배포 서버의 원정대 목록 호출은 아직 확인하지 않았습니다. 테스트는 운영 DB나 실제 API 키를 사용하지 않았습니다.
