# Codex 활용과 코드 검증 기록

이 문서는 저장소 커밋, 테스트 기록, 개발 대화를 바탕으로 2026-11-13에 작성한 **사후 정리**입니다. 아래 요구사항은 당시 대화를 요약한 것이며 원본 프롬프트 전문이나 당시 작성된 PR 기록을 대신하지 않습니다.

## 1. 역할과 증거를 구분하기

- 사용자: 서비스 방향과 기능 우선순위를 정하고, 디자인·사용 횟수·무료 배포 등 요구사항을 전달했습니다. 실제 이용 중 검색 실패, 빈 화면/데이터 미표시 등을 보고하고 코드 설명을 요청했습니다.
- Codex: 구현안을 제안하고 코드를 작성·수정했으며, 테스트·빌드·모의 API 측정과 일부 실제 브라우저/HTTP 확인을 수행했습니다. 커밋과 push도 사용자의 허용 범위에서 수행했습니다.
- 아직 확인할 점: 문서가 있다는 사실만으로 사용자가 모든 코드를 직접 검토하거나 테스트를 손으로 실행했다고 증명되지는 않습니다. 본인이 읽고 재현한 부분을 별도로 기록해야 합니다.
- 현재까지 main 직접 커밋 방식으로 진행했습니다. 실제로 없는 코드 리뷰 PR, 팀 협업, CI 자동화 이력을 사후에 만들었다고 표현하지 않습니다.

## 2. 앞으로 작업마다 남길 기록

[작업 기록 양식](templates/ai-task-record.md)을 기능별로 복사해 사용합니다. 예: docs/records/2026-11-13-roster.md. 새 폴더/파일은 다음 실제 작업에서 만들면 됩니다.

1. **요구사항**: 만들 행동, 범위, 유지할 동작, 하지 않을 일을 적습니다.
2. **검증 기준**: 정상 동작뿐 아니라 빈 응답, 외부 장애, 중복 클릭, 날짜 경계 등 구체적인 조건을 먼저 정합니다.
3. **제안과 선택**: 제안자, 선택한 방식, 선택 이유와 포기한 대안을 구분합니다.
4. **확인과 수정**: 읽은 코드, 실패 재현, 예상/실제 결과, 바뀐 파일과 커밋을 연결합니다.
5. **검증 결과**: 명령·실행일·환경·수행자·실패/통과·검증하지 않은 범위를 적습니다.
6. **다음 작업**: 남은 위험, 본인이 더 공부할 부분을 남기고 TASK_PROGRESS.md에 이어갈 순서를 적습니다.

대화 전체를 올리기보다 관련 요구사항과 결과를 짧게 요약합니다. 명령에 포함된 비밀값, 인증 헤더, DB 접속 URI와 개인정보를 제거하고 공유합니다. 오류 원인을 확정하지 못했으면 '추정'으로 남깁니다.

## 4. 생성된 코드가 그대로 정답이 아니었던 사례

### 4-1. 개발 환경에서는 통과했지만 배포 설치가 실패

- 증상: Vercel의 npm ci에서 ERESOLVE 발생.
- 근거: eslint-plugin-oxlint의 peer 요구 버전과 oxlint 버전이 맞지 않았습니다.
- 수정: 두 패키지를 1.73.0으로 맞추고 lockfile 반영. 별도로 플랫폼별 네이티브 패키지 직접 의존도 정리했습니다.
- 핵심: 로컬 node_modules가 남아 있는 상태의 성공만으로 배포 가능하다고 판단할 수 없습니다.
- 근거 커밋: [버전 충돌](https://github.com/Cheol-Jin/loatask/commit/ac327c9), [플랫폼 패키지](https://github.com/Cheol-Jin/loatask/commit/2039c83).

### 4-2. 기본 프로필 데이터가 화면에 나오지 않음

- 증상: 검색 기능이 있어도 프로필 일부 필드가 표시되지 않았습니다.
- 원인: 공식 API 필드와 클라이언트 모델의 이름 차이를 매핑하지 않은 부분.
- 수정: JsonAlias로 입력 필드를 매핑하고 출력 camelCase를 유지. Mock API 기반 매핑/오류 테스트 추가.
- 확인 기준: HTTP 성공 여부뿐 아니라 실제 필드 이름과 값이 프론트에서 사용 가능한 형태인지 확인.
- 근거: [3a12a86](https://github.com/Cheol-Jin/loatask/commit/3a12a86).

### 4-3. DB 연결은 성공했지만 공식 API HTTPS 연결 실패

- 증상: Render 서버와 DB는 실행됐지만 캐릭터 API가 연결 오류를 반환.
- 확인: Codex가 로컬 재현에서 DB CA만 든 truststore는 TLS 검증에 실패하고, 기본 공인 CA를 병합한 저장소는 인증 없이 공식 API까지 연결돼 401을 받는 것을 비교했습니다.
- 수정: Java 기본 공인 인증서를 복사한 뒤 Aiven CA를 추가. 인증서 검증을 끄지 않았습니다.
- 결과: 수정 배포 뒤 실제 캐릭터 조회 HTTP 200 및 화면 프로필 확인.
- 근거: [c69a451](https://github.com/Cheol-Jin/loatask/commit/c69a451), docker-entrypoint.sh.
- 학습점: 한 외부 서비스에 맞춘 신뢰 설정이 다른 HTTPS 연결에 미치는 영향까지 확인해야 합니다.

### 4-4. API 값은 정상이어도 표시 의미가 잘못됨

- 증상: 실제 화면 검증에서 선택 트라이포드가 0·1·2단계로 표시.
- 수정: API의 인덱스를 화면에서 1·2·3단계로 변환.
- 결과: 배포 화면에서 1~3단계 표시 확인.
- 근거: [4a632d5](https://github.com/Cheol-Jin/loatask/commit/4a632d5).
- 학습점: 타입 검사와 JSON 매핑이 통과해도 사용자가 이해하는 값으로 표시되는지는 별도로 봐야 합니다.

### 4-5. 로컬 테스트는 통과했지만 배포 홈에서 세 영역이 실패

- 사용자 보고: 소식·이벤트·누적 순위가 표시되지 않음.
- 확인: 세 API의 실제 HTTP 200과 CORS 허용을 확인한 뒤 페이지 새로고침으로 실제 데이터 표시를 확인했습니다.
- 코드 수정: 없음.
- 원인: 배포/재기동 시점의 실패 상태가 남았을 가능성은 있으나 **최초 실패 원인은 확정하지 못했습니다**.
- 학습점: 모의 테스트 성공, 배포 프로세스 성공, 실제 사용자 화면 정상은 서로 다른 증거입니다. 확인하지 않은 원인을 해결했다고 쓰지 않습니다.

## 5. 검토 기준과 사용한 검증

| 기준 | 확인한 사례 |
| --- | --- |
| 계약 정확성 | JsonAlias 매핑, 빈 프로필/잘못된 JSON 처리, 원정대 배열 필드 |
| 오류 분류 | 404/401/429/5xx/연결 실패 구분, 외부 원문 오류와 인증정보 비노출 |
| 최신성과 가용성 | 캐시 60초 갱신, 마지막 성공 데이터 최대 10분, 실패가 성공 시점을 연장하지 않음 |
| 동시성 | 같은 키 갱신 병합, 다른 키 요청의 독립 처리 |
| 상태 저장 | 즐겨찾기·최근 검색·운세 localStorage 저장 실패 처리, 결과 복원 |
| 날짜/사용 제한 | KST 자정, 항목별 2회, 재추첨 제외. 로그인 없는 브라우저 제한이라는 한계 명시 |
| 화면 상태 | 검색→홈 전환, 오류 영역별 재시도, 다른 캐릭터 이동, 실제 데이터 표시 |
| 배포 재현 | npm ci, Node 버전, Linux 패키지, Java CA, 환경변수, 기존 Git 변경 보존 |

## 6. 앞으로 복사해 사용할 요청 예시

이 예시는 앞으로 사용할 제안이며, 과거 원본 프롬프트가 아닙니다.

```text
기능: 캐릭터 목록의 서버 필터 개선.

먼저 TASK_PROGRESS.md와 Git 상태를 확인하고 기존 변경을 보존해 줘.
기존 검색 URL, 응답 형식, 검색 횟수 집계는 유지해 줘.
서버를 바꿀 때 추가 공식 API 호출이 없어야 해.

수정 전에 영향을 받는 파일과 구현 선택지를 짧게 설명해 줘.
수정 후에는 빈 목록, 서버 변경, 다른 캐릭터 이동을 확인해 줘.
검증한 명령과 결과, 실제 서비스에서 확인하지 못한 부분을 구분해 줘.
문서에 내가 요청한 내용과 Codex가 제안한 정책을 따로 기록해 줘.
```

OpenAI 공식 안내도 원하는 행동·관련 코드/재현 절차·제약·검증 방법을 요청에 포함하는 방식을 설명합니다: [Prompting Codex](https://learn.chatgpt.com/docs/prompting?site_variant=chatgpt).

## 7. 사용자가 직접 채워야 하는 부분

- 어떤 코드를 직접 읽었고, 어떤 설명을 다시 요청했는지.
- 어떤 테스트를 직접 실행했고, 예상과 실제 결과를 비교했는지.
- 다른 방식으로 구현한다면 무엇을 바꿀 수 있는지.
- 면접에서 코드 없이 설명 가능한 범위가 어디까지인지.

지금 문서를 작성한 사실과 과거 수행 내용을 구분하고, 향후 직접 확인한 내용에만 날짜와 결과를 추가합니다.
